= 结构化写法速查

[cols="1,2", options="header"]
|===
|写法 |含义

|`= 书名`
|书名（Document Title）。写在文件第一行，一本书只有一个。

|`= 部名`
|一部（Part，0 级）。书名之后再写一个等号的标题，就是一部。

|`== 章`
|一章（Chapter，1 级）。

|`=== 节`
|章里的一节（2 级）。

|`==== 小节`
|3 级。

|`===== 小节`
|4 级。

|`====== 小节`
|5 级，AsciiDoc 最深的一层。

|`parts/010-topic/`
|部目录的编排号：三位定宽，默认步长 10（`010`、`020`……），末位留作插入。

|`010-opening.adoc`
|章文件的编排号，规则与部目录相同。

|`[.dish]`
|role：这一节在书里是什么。

|`[#红烧肉的火候]`
|custom ID：一节要被单独引用、又与别的标题同名时，给它的第二个地址。

|`[.dish, 难度=中]`
|role 加上写在 attrlist 里的字段。

|`主料:: 五花肉一斤`
|标题下第一个描述列表里的字段。字段多，或值要换行时这样写。

|字段文字下一行的 `+`，再接一个块
|把引文、代码块或表格挂到字段上，块属于这个字段的值。

|`pass:[xref:红烧肉[]]`
|普通引用，投影为 `aat:references`。

|`pass:[xref:炒糖色[rel=depends-on]]`
|带关系谓词的引用，投影为以谓词命名的边 `rel:depends-on`。

|`[.convention, declares=roles]`
|约定声明：标题下的描述列表是 role 的词表。`declares` 还可以取 `relations`、`values`（配 `for` 与 `field`）和 `fields`（配 `for`）。
|===

标题层级要连续，不跳级。附录、术语表和参考文献前面写 `[appendix]`、`[glossary]`、`[bibliography]` 这样的 section style；书没有分部时，它们写成 `==`，与各章并列；书有分部时，写成 `=`，与各部并列，写成 `==` 会成为前一部的子节。写成 `=` 的附录按 1 级算，附录的第一层小节写 `===`。附录标题不写序号，字母由 Asciidoctor 生成，前面的词由书头的 `:appendix-caption:` 决定。前言、致谢等前置部分在第一部之前，有没有分部都写 `==`。

同一本书里经 include 拼起来的各个文件之间，引用直接写标题。引用另一本书时，在书头定义一个文档属性，存那本书的入口路径（如 `:book-b: ../book-b/book.adoc`），引用写成 `pass:[xref:{book-b}#目标标题[]]`，`#` 后面写那本书里的标题。

反引号只改字体：反引号里的行内宏（如 xref）和属性引用照样会被替换。要原样展示它们，用 `\pass:[…]` 包住，外面再加反引号得到等宽字体。`= 书名`、`[.dish]` 这类块写法出现在行内时不会被当作结构，反引号就够了。

每一种写法怎样选，见 xref:结构化写法决策树[]。
