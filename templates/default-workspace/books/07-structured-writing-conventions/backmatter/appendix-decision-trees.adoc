= 结构化写法决策树

=== 写一个新标题

触发场景:: 作者要在书里加一个标题。

[source,text]
----
1. 这是书名吗？
   ├─ 是：写 `= 书名`，放在文件第一行。结束。
   └─ 否：看第 2 步。

2. 这是附录、术语表或参考文献吗？
   ├─ 是：在标题上方写对应的 section style：
   │      `[appendix]`、`[glossary]` 或 `[bibliography]`。
   │      section style 只改这一节的语义，层级仍由等号的个数决定。
   │      书没有分部时，写成 `==`，与各章并列。
   │      书有分部时，写成 `=`，与各部并列；若写成 `==`，它会成为前一部的子节。
   │      附录的第一层小节写 `===`。写成 `=` 的附录在解析时被调到 1 级，
   │      它下面的 `==` 却不跟着调，因此会跑出附录，成了排在附录后面的章。
   │      附录标题不写“附录 A”，因为字母由 Asciidoctor 生成，前面的词由书头的 `:appendix-caption:` 决定。
   │      结束。
   └─ 否：看第 3 步。

3. 这是前言、致谢、献辞或版本说明吗？
   ├─ 是：在标题上方写 `[preface]`、`[acknowledgments]`、`[dedication]` 或 `[colophon]`，
   │      放在第一部之前，有没有分部都写成 `==`。结束。
   └─ 否：看第 4 步。

4. 它和上一级标题之间跳级了吗？
   │  写成 `=` 的附录、术语表和参考文献按 1 级算，所以附录下写 `===` 不算跳级。
   ├─ 是：补上中间那一级标题，再回到第 4 步。
   └─ 否：看第 5 步。

5. 这一节里有没有一段，以后要被单独引用？
   ├─ 是：用下一级标题把那一段划出来，让引用指向新标题，再让新标题另走一遍这棵树。结束。
   └─ 否：照写这个标题。结束。
----

=== 改名

触发场景:: 作者发现标题已经不是这一节现在的名字。

[source,text]
----
1. 只是换一个更准确的名字吗？
   ├─ 是：改标题。工作区的检查会逐处报出还写着旧名字的引用，照着改成新名字。
   │      旧名字值得让读者查到时，把它写进别名。结束。
   └─ 否：看第 2 步。

2. 这一节收的范围变了吗？
   ├─ 是：改标题，并重读这一节的说明、收什么与不收什么、相关的节和已经写下的结论。
   │      对检查报出的每一处旧引用，先判断它说的是留下的部分还是去掉的部分，
   │      再决定改成新名字，还是改指别的一节。看第 3 步。
   └─ 否：看第 3 步。

3. 这一节被拆开，或不再使用了吗？
   ├─ 是：不留它。删掉它，或把它改成拆出来的某一节的名字。
   │      检查会逐处报出旧引用，逐一判断每一处该改指哪一节。结束。
   └─ 否：结束。
----

=== 给标题写 role

触发场景:: 作者要说明一节在书里是什么。
前提:: 书里已经声明了 role 的词表，例如 `dish`、`technique`、`concept`。

[source,text]
----
1. 这一节要被查询当作某种 role 找到吗（例如列出全书的菜）？
   ├─ 否：不写 role。它是父标题下的一节，读的人照上下文理解。结束。
   └─ 是：看第 2 步。

2. 词表里有这个 role 吗？
   ├─ 是：写在这一节自己的 attrlist 里，例如 `[.technique]`。
   │      role 只属于写了它的标题，所以下级标题要被当作某种 role 时，也在它自己的标题上写上。结束。
   └─ 否：先把它加进 role 的声明（见《改约定》），再写。结束。
----

=== 提到另一节

触发场景:: 作者在正文里要提到别的部、章或节。

[source,text]
----
1. 目标在另一本书里吗？
   │  无论在哪里，都写 xref，不写“上一章”“第二部讲过”这样的位置词。
   ├─ 是：在书头用文档属性存那本书的入口路径，例如 `:snack-book: ../02-home-snacks/book.adoc`。
   │      xref 写 `{snack-book}#糖油饼[]`，`#` 后面写那本书里的标题。看第 2 步。
   └─ 否：同一本书里经 include 拼起来的各个文件之间，xref 直接写标题。看第 2 步。

2. 目标标题在它所在的书里与别的标题同名吗？
   ├─ 是：在要引用的那一节标题上方加 custom ID（上级标题加本节标题，如 `红烧肉的火候`），
   │      xref 写这个 ID，并写上显示文本。看第 3 步。
   └─ 否：xref 写标题原文，不必写显示文本。看第 3 步。

3. 要说出两节之间是什么关系吗？
   ├─ 否：写普通 xref，例如 `xref:红烧肉[]`，投影为 `aat:references`。
   │      “先读那一节”这类阅读建议也写普通 xref。结束。
   └─ 是：看第 4 步。

4. 从本书声明过的关系谓词里选一个，写进 `rel`。要用的谓词还没声明时，先把它写进关系谓词的声明。
   投影为以谓词命名的边，例如 `rel:depends-on`。常见的几种：
   ├─ 当前标题的做法、规则或判断以目标标题为依据：`rel=depends-on`。
   ├─ 当前标题是目标标题的一个例子：`rel=illustrates`。
   ├─ 当前标题给出目标标题所指之物的定义：`rel=defines`。
   └─ 当前标题限定目标标题的做法或范围：`rel=constrains`。
   结束。
----

=== 写字段

触发场景:: 作者要给一节或一条引用写上几项信息。

[source,text]
----
1. 这几项信息属于一条引用吗？
   ├─ 是：写在 xref 的方括号里，和 `rel` 并列，
   │      例如 `xref:红烧肉[rel=adapted-from, 改动=糖色全用冰糖]`。结束。
   └─ 否：看第 2 步。

2. 书的约定声明过这个字段吗？
   ├─ 是：照声明写。`declares=values` 声明的，写在 attrlist 里，取值在列表里，
   │      例如 `[.dish, 难度=中]`；`declares=fields` 声明的，写在标题下第一个描述列表里，
   │      例如 `主料:: 五花肉一斤`。看第 4 步。
   └─ 否：看第 3 步。

3. 它的取值有限、又短吗？
   ├─ 是：写在标题前的 attrlist 里。要这种 role 的标题都写它时，把它和它的取值写进 `declares=values` 的声明。结束。
   └─ 否：写在标题下第一个描述列表里。要这种 role 的标题都写它时，把它写进 `declares=fields` 的声明。看第 4 步。

4. 字段的值要带引文、代码块或表格吗？
   ├─ 是：在字段文字的下一行写 `+`，再写那个块，块属于这个字段的值。
   │      字段之间不放不带 `+` 的块，否则字段列表在那个块之前就结束了。结束。
   └─ 否：结束。
----

=== 改约定

触发场景:: 作者要给书加、改或删一个 role、关系谓词、字段或字段的取值。

[source,text]
----
1. 书里已有这一类的声明吗？
   ├─ 是：在那条声明的描述列表里加、改或删条目。看第 2 步。
   └─ 否：新建一个声明标题，放在凡例里（前言之后的 `[preface]` `== 凡例`），
          标题上写 `[.convention, declares=...]`。看第 2 步。

2. 声明的是什么？
   ├─ role：`declares=roles`。
   ├─ 关系谓词：`declares=relations`。
   ├─ 某种 role 的标题必须在 attrlist 里写的字段与它的取值：`declares=values, for=<role>, field=<字段名>`。
   └─ 某种 role 的标题下描述列表里必须写出的字段：`declares=fields, for=<role>`。
   看第 3 步。

3. 条目的词写成写作时用的那个词了吗？
   ├─ 否：去掉点号和反引号，例如 `.dish` 写成 `dish`，再回到这一步。
   └─ 是：在描述里写出这个词的意思。结束。
----

约定要变时，应先改声明，再照新的声明改书里用到它的地方。

=== 给源文件取编排号

触发场景:: 作者要给部目录或章文件取编排号。
前提:: 编排号写三位，默认步长为 10，例如 `010`、`020`、`030`；始终写满三位。

[source,text]
----
1. 新文件排在最后，还是排在两个文件之间？
   ├─ 排在最后：取比当前最大编排号大的下一个整十。
   │      `090` 之后是 `100`，`015` 之后是 `020`。结束。
   └─ 排在 A 与 B 之间：取两个编排号的中间值，例如 `010` 与 `020` 之间用 `015`。
          中间值不是整数时，取它两侧任一个整数，例如 `010` 与 `015` 之间用 `012` 或 `013`。结束。
----

=== 原样展示写法

触发场景:: 作者要在正文里展示一段标记、代码或日志。

[source,text]
----
1. 要在行内原样展示行内宏（如 xref）或属性引用吗？
   │  反引号只改字体，里面的行内宏和属性引用照样会被替换；
   │  `= 书名`、`[.dish]` 这类块写法在行内不会被当作结构，反引号就够了。
   ├─ 是：用 `pass:[…]` 包住；要等宽字体，再在外面加反引号。结束。
   └─ 否：看第 2 步。

2. 是代码或日志，又要逐行配上文字解释吗？
   ├─ 是：用 AsciiDoc 的 callouts，在代码里标上号，再在代码块下面按号解释。结束。
   └─ 否：照常写。结束。
----
