== 字段

一节除了名字和 role，常常还有几项信息，例如一道菜的难度、主料、用时和出处。这些信息写成字段，写在标题前的 attrlist 里，或标题下的描述列表里：

[source,asciidoc]
----
[.dish, 难度=中]
== 红烧肉

主料:: 五花肉一斤
用时:: 一个半小时
出处:: 《随园食单·须知单·火候须知》
+
____
熟物之法，最重火候。有须武火者，煎炒是也；火弱则物疲矣。有须文火者，煨煮是也；火猛则物枯矣。有先用武火而后用文火者，收汤之物是也；性急则皮焦而里不熟矣。
____

五花肉切块，大火烧开，转小火炖到收汁。
----

`.dish` 是 role；`难度=中` 是写在 attrlist 里的字段；`主料`、`用时`、`出处` 是标题下描述列表里的字段。投影时它们都成为这一节的字段，谓词是 `field:` 加上字段名原文，例如 `难度` 成为 `field:难度`，`主料` 成为 `field:主料`。

书的约定声明过的字段，应照声明写在对应的位置：声明了取值的（如难度）写在 attrlist 里，要求写出的（如主料、用时）写在标题下第一个描述列表里（见《xref:声明本书的约定[]》）。设计一个新字段时，取值有限的短字段宜放在 attrlist 里，如难度；要写成句子或要挂一个块的，宜放在描述列表里，如主料和出处。

写在 attrlist 里的字段名应只用字、数字、`_` 和 `-`。名字里带顿号、点号或空格时，Asciidoctor 把这一整项当作位置属性，它不成为字段，例如 `[.dish, 葱、姜=多]` 里的 `葱、姜=多`。这样的名字应写进描述列表，例如 `葱、姜:: 多放`。

字段的值要带一段引文、一个代码块或一张表时，应在字段文字的下一行写 `+`，再写那个块。挂上来的块属于这个字段的值。上面的 `出处` 就是这样，它的值是“《随园食单·须知单·火候须知》”这一行，加上挂上来的那段原文。字段的值按源文本原样保存，反引号、xref 和 include 指令都按写下的样子保留。

没有用 `+` 挂上的块不属于字段。字段列表在这个块之前结束，块和它后面的内容都是这一节的正文，块后面再写的描述列表也不再是字段。因此，字段之间要放块时，应以 `+` 挂上，不应直接插入。

另有三种写法，会让标题下的描述列表整串都不算字段，这一节一个字段也得不到：

* 标题和描述列表之间隔着别的块，如段落、提示块、代码块、图片；
* 描述列表带了 style（如 `[horizontal]`）、ID、块标题或别的块属性；
* 某个条目里又嵌套了描述列表。

相反，如果标题正下方的描述列表要作为正文、而不作为字段，可在它前面写一段导语，或给它加上 `[horizontal]` 这样的 style。

引用也可带字段，和 `rel` 一起写在 xref 的方括号里：

[source,asciidoc]
----
[.dish, 难度=易]
== 冰糖红烧肉

由《xref:红烧肉[rel=adapted-from, 改动=糖色全用冰糖]》改良而来。
----

`改动=糖色全用冰糖` 是这条引用的字段，投影时记在这条 xref 的边上，不记在《冰糖红烧肉》这一节上。

字段叫什么、取哪些值，由书自己定，但一个字段在全书里应只表示一件事。某种 role 要求写出的字段和它可取的值，应写进约定声明；别名、出处这类可写可不写的字段，不必声明。
