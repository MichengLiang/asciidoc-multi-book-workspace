== 标题、寻址与引用

作者用等号行写标题，等号的个数决定标题的层级。标题前的 attrlist 里能写 role 和字段。

[source,asciidoc]
----
[.dish]
== 红烧肉
----

`.dish` 表明这个标题在书里是一道菜，`红烧肉` 是它现在的名字。

引用一个标题时，xref 的目标应写它的标题原文。正文提到别的部、章、节时，应写成 xref，并在外面加书名号（见《xref:篇名用书名号[]》）。位置词会随编排调整而指错地方，读者也无法从位置词跳到那一节，因此不应写“上一章”“第二部讲过”这类位置词。

[source,asciidoc]
----
做法同《xref:红烧肉[]》，排骨焯水的时间短一些。
----

这条 xref 投影为默认的引用谓词 `aat:references`。要表明两节之间是什么关系，就在 xref 里写 `rel`：

[source,asciidoc]
----
红烧肉的红亮来自糖色，不会《xref:炒糖色[rel=depends-on]》就做不成这道菜。
----

`rel=depends-on` 表明写这条 xref 的那一节以它指向的那一节为依据，投影为 `rel:depends-on`。哪些关系算依据、哪些只是请读者参看，见《xref:关系谓词[]》。

标题里的空格、顿号和冒号，引用时应照原文写。`pass:[xref:葱、姜、蒜的处理[]]` 与 `pass:[xref:红烧肉[]]` 一样能找到标题。标题原文是标题的地址；作者另写 custom ID 时，custom ID 是它的第二个地址。

Asciidoctor 还会从标题生成一个 ID，生成时去掉标点，同名的按出现的先后加上 `-2`、`-3`。这个 ID 随标题和标题的位置变化，因此引用不应写它。

工作区的构建（`pnpm run build` 与 `pnpm run check`）按地址核对每一处引用：找不到目标，或目标不止一个，就报出引用所在的文件与行；找到了，就把 HTML 里的链接接到那个标题上。单独用 Asciidoctor 或编辑器预览时情形不同。Asciidoctor 把不含空格的引用目标当作 ID 去找，而它生成的 ID 去掉了标点，因此目标不含空格、却带顿号或冒号的引用，以及下面要讲的限定地址，在预览里是断的。这时源文件并没有写错，应以工作区的构建为准。

写完以后，在工作区的根目录运行 `pnpm run check`。它核对三件事：每一处引用都找到了唯一的目标；include 进来的文件都在工作区里；HTML 里引用的图片等资源都在。role、字段和字段的取值应照凡例里的声明写，这几项由作者自己核对。

标题会重名。按类别组织的书，各个大标题下常有名字相同的小节：

[source,asciidoc]
----
== 红烧肉

=== 火候

== 清蒸鲈鱼

=== 火候

== 糖醋排骨

=== 火候
----

三节《火候》各讲一道菜，一般不会被单独引用。某一处要指向《红烧肉》下的《火候》时，`pass:[xref:火候[]]` 有三个候选，检查会报出引用所在的位置和三节各自的位置。这时应把上级标题写在前面，用 `::` 隔开：

[source,asciidoc]
----
糖色下锅以后怎样转火，见《xref:红烧肉::火候[红烧肉·火候]》。
----

`红烧肉::火候` 是这一节的限定地址。写限定地址时，应符合下列规定：

* 上级标题由近及远逐级补上，补到只剩一个标题为止，最多补到最上一级的标题；
* 写上显示文本，上级标题与本节标题之间用间隔号，例如 `红烧肉·火候`（见《xref:篇名用书名号[]》）。

不写显示文本时，链接上只显示最后一级标题“火候”，读者看不出是哪道菜的。

有两种标题当不了地址：同一个上级下有两个同名的标题，限定地址补到最上一级的标题也分不开它们；标题原文里带 `#` 或 `::`，引用会把它们当作分隔。要引用这样的一节时，应在它的标题上方加 custom ID（`[#…]`），引用写这个 ID。custom ID 是同一个标题的第二个地址，标题原文仍是它的地址。作者是在要引用某一节时才发现标题当不了地址的，custom ID 也宜在那时再加，不必预先写下。

标题改名以后，检查会逐处报出仍写着旧名字的引用，限定地址里写着旧名字的也一样，因为书的全部源文件都在同一个工作区里，每一处引用都在检查的范围之内，作者依报告逐处改正即可。预先写下的 ID 会让旧引用在改名后照常找到目标，这些引用便躲过了检查，ID 里也留下了旧的说法。因此，标题当得了地址时，不应写 custom ID。

role 只属于写了它的那个标题。希望查询工具把某个下级标题当作某种 role 列出时，应在它自己的标题上写这个 role。没有写 role 的下级标题只是父标题下的一节，读者按上下文理解它。

[source,asciidoc]
----
[.dish]
== 红烧肉

=== 火候

[.technique]
=== 炒糖色
----

《火候》没有写 role，它是《红烧肉》下的一节；《炒糖色》写了 `.technique`，查询技法时会列出它。
