== 标题、寻址与引用

作者用等号行写标题，等号的个数定层级。标题前的 attrlist 可以写 role 和字段。

[source,asciidoc]
----
[.dish]
== 红烧肉
----

`.dish` 说明这个标题在书里是一道菜，`红烧肉` 是它现在的名字。

引用一个标题，xref 的目标写它的标题原文：

[source,asciidoc]
----
做法同 xref:红烧肉[]，排骨焯水的时间短一些。
----

这条 xref 投影为 `aat:references`，默认的引用谓词。要说出两节之间是什么关系，在 xref 里写 `rel`：

[source,asciidoc]
----
红烧肉的红亮靠糖色，先学会 xref:炒糖色[rel=depends-on]。
----

`rel=depends-on` 说明当前标题以目标标题为依据，投影为 `rel:depends-on`。

标题里的空格、顿号和冒号，引用时都照原文写：`pass:[xref:葱、姜、蒜的处理[]]` 与 `pass:[xref:红烧肉[]]` 一样能找到标题。标题原文是标题的地址；作者另写 custom ID 时，custom ID 是它的第二个地址。

Asciidoctor 还会从标题生成一个 ID：去掉标点，同名时按出现的先后加上 `-2`、`-3`。这个 ID 跟着标题和标题的位置变，引用不写它。

工作区的构建（`pnpm run build` 与 `pnpm run check`）按地址核对每一处引用：找不到目标，或目标不止一个，就报出引用所在的文件与行；找到了，就把 HTML 里的链接接到那个标题上。单独用 Asciidoctor 或编辑器预览时，没有空格、又带顿号或冒号的标题会被当成 ID 去找，预览里这样的链接是断的。源文件没有写错，以工作区的构建为准。

标题会重名。按类别组织的书，各个大标题下常有名字相同的小节：

[source,asciidoc]
----
== 红烧肉

=== 火候

== 清蒸鲈鱼

=== 火候

== 糖醋排骨

=== 火候
----

三节《火候》各讲一道菜，平时不必单独引用。某一处要指向红烧肉的《火候》时，`pass:[xref:火候[]]` 有三个候选，检查会报出引用所在的位置和三节各自的位置。这时在要引用的那一节标题上方加 custom ID（`[#…]`），引用写这个 ID：

[source,asciidoc]
----
== 红烧肉

[#红烧肉的火候]
=== 火候
----

给 custom ID 起一个在全书里能单独说清这一节的名字，例如上级标题加本节标题。引用写这个 ID，并写上显示文本：`pass:[xref:红烧肉的火候[红烧肉的火候]]`。不写显示文本，链接上显示的是这一节的标题“火候”，读者看不出是哪道菜的。

custom ID 是同一个标题的第二个地址，标题原文仍是它的地址。重名是在要引用的那一刻发现的，custom ID 也在那一刻才加。

不需要单独引用、也不重名的标题，不写 custom ID。标题改了名，引用它的地方要一起接受检查：书都在本地，检查覆盖每一处引用，没有跟上的会逐处报出来。为了让旧引用在改名后照常找到目标而预先写下的 ID，让这些引用躲过了检查，ID 里还留着旧的说法。

[TIP]
====
1. custom ID 只在一节需要被单独引用、又与别的标题同名时才加，其余时候标题直接作地址。写法速查见 xref:结构化写法速查[]；完整的判断流程见 xref:结构化写法决策树[]。
2. 正文提到别的部、章、节时，写成 xref，不写“上一章”“第二部讲过”这样的位置词：位置会随编排改变，读者也没法从位置词跳过去。
====

role 只属于写了它的那个标题。下级标题要被检查和查询当作某种 role，就在它自己的标题上写这个 role；不写，它是父标题下的一节，读的人照上下文理解。

[source,asciidoc]
----
[.dish]
== 红烧肉

=== 火候

[.technique]
=== 炒糖色
----

《火候》没有写 role，它是红烧肉下的一节；《炒糖色》写了 `.technique`，查询技法时会列出它。
