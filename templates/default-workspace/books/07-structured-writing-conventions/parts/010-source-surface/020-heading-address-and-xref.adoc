== 标题、寻址与引用

作者用等号行写标题，等号的个数决定标题的层级。标题前的 attrlist 里能写 role 和字段。

[source,asciidoc]
----
[.dish]
== 红烧肉
----

`.dish` 表明这个标题在书里是一道菜，`红烧肉` 是它现在的名字。

引用一个标题时，xref 的目标应写它的标题原文。正文提到别的部、章、节时，应写成 xref，并在外面加书名号（见《xref:篇名用书名号[]》）。位置词会随编排调整而指错地方，读者也无法从位置词跳到那一节，因此不应写“上一章”“第二部讲过”这类位置词。

[source,asciidoc]
----
做法同《xref:红烧肉[]》，排骨焯水的时间短一些。
----

这条 xref 投影为默认的引用谓词 `aat:references`。要表明两节之间是什么关系，就在 xref 里写 `rel`：

[source,asciidoc]
----
红烧肉的红亮来自糖色，不会《xref:炒糖色[rel=depends-on]》就做不成这道菜。
----

`rel=depends-on` 表明写这条 xref 的那一节以它指向的那一节为依据，投影为 `rel:depends-on`。哪些关系算依据、哪些只是请读者参看，见《xref:关系谓词[]》。

标题里的空格、顿号和冒号，引用时应照原文写。`pass:[xref:葱、姜、蒜的处理[]]` 与 `pass:[xref:红烧肉[]]` 一样能找到标题。标题原文是标题的地址；作者另写 custom ID 时，custom ID 是它的第二个地址。

Asciidoctor 还会从标题生成一个 ID，生成时去掉标点，同名的按出现的先后加上 `-2`、`-3`。这个 ID 随标题和标题的位置变化，因此引用不应写它。

工作区的构建（`pnpm run build`）按地址把网页上的链接接到那一节。引用找不到目标，或者目标不止一节，一条链接只能跳到一处，构建便不改它，留下 Asciidoctor 写的样子，网页上这条链接是断的。单独用 Asciidoctor 或编辑器预览时，链接都照 Asciidoctor 自己的规则走：它把不含空格的引用目标当作 ID 去找，而它生成的 ID 去掉了标点，因此目标不含空格、却带顿号或冒号的引用，以及下面要讲的限定地址，在预览里是断的。这时源文件并没有写错，应以工作区的构建为准。

构建只在做不出页面时失败，例如 include 进来的文件不在工作区里。引用找不到目标或目标不止一节，构建照常完成；哪些引用断了，由读投影的工具检查，它读的就是《xref:源文本与投影[]》里的那张图。role、字段和字段的取值应照凡例里的声明写。

标题会重名。按类别组织的书，各个大标题下常有名字相同的小节：

[source,asciidoc]
----
== 红烧肉

=== 火候

== 清蒸鲈鱼

=== 火候

== 糖醋排骨

=== 火候
----

三节《火候》各讲一道菜，一般不会被单独引用。某一处要指向《红烧肉》下的《火候》时，`pass:[xref:火候[]]` 对上三节，网页上的链接不知该跳到哪一节，读投影的工具会把这处引用连同三节各自的位置报出来。这时应把上级标题写在前面，用 `::` 隔开：

[source,asciidoc]
----
糖色下锅以后怎样转火，见《xref:红烧肉::火候[红烧肉·火候]》。
----

`红烧肉::火候` 是这一节的限定地址。写限定地址时，应符合下列规定：

* 上级标题由近及远逐级补上，补到候选只剩一个为止；
* 写上显示文本，各级标题之间用间隔号，例如 `红烧肉·火候`（见《xref:篇名用书名号[]》）。

不写显示文本时，链接上只显示最后一级标题“火候”，读者看不出是哪道菜的。

补一级不够时，再往上补一级。例如菜谱分了《家常菜》《宴客菜》两部，两部里都有《红烧肉》，引用家常菜里那一道的火候时，写 `pass:[xref:家常菜::红烧肉::火候[家常菜·红烧肉·火候]]`。补到书名之下最高的一级（分部的书是部，不分部的书是章），就是这一节完整的路径；书名全书只有一个，不必写。

同一个上级下有两个同名的标题时，完整的路径也分不开它们，例如糖醋排骨要炸两遍，《糖醋排骨》下写了两节《炸》。两节同名，多半是标题没有说清这一节讲什么。这时宜先改标题，例如改成《初炸》与《复炸》，改好以后，两节的标题各是各的地址。

标题改不了时，标题和限定地址都指不出唯一的一节。还有两种标题，按原文写不出引用：标题原文里带 `#` 或 `::` 的，引用会把它们当作分隔；标题以行内标记开头的，例如 `+`book.adoc` 的职责+`，AsciiDoc 不把以反引号、星号这类标记起头的目标读成引用。要引用这样的一节，应在它的标题上方加 custom ID（`[#…]`），引用写这个 ID。加 custom ID 时，应符合下列规定：

* 名字说清这一节讲什么，不写序号和位置词，例如不写 `炸-2`、`第二个炸`，因为序号和位置会随编排变化；
* 名字不与书里的任何标题相同，否则这个地址对上两节，引用它的链接仍然是断的；
* 同一个上级下同名的几节，要引用哪一节，就给哪一节加；只给其中一节加时，另一节的标题和限定地址仍然有两个候选；
* 引用写上显示文本，写出能让读者分清是哪一节的说法。

custom ID 是同一个标题的第二个地址，不替代标题。作者是在要引用某一节时才发现标题当不了地址的，custom ID 也宜在那时再加，不必预先写下。

标题改名以后，按旧名字写的引用都找不到目标，网页上的这些链接是断的。按旧名字写的引用，地址里都含着旧名字，限定地址也一样，因此改名时在书里搜一遍旧名字，就能找到每一处引用，连同显示文本和正文里写着的旧名字，作者逐处改正即可。预先写下的 ID 会让旧引用在改名后照常落到这一节：这些引用写的是 ID，里面没有旧名字，搜旧名字搜不到它们，可这一节讲的可能已不是它们当初要指的事，ID 里也留下了旧的说法。因此，标题当得了地址时，不应写 custom ID。

role 只属于写了它的那个标题。希望查询工具把某个下级标题当作某种 role 列出时，应在它自己的标题上写这个 role。没有写 role 的下级标题只是父标题下的一节，读者按上下文理解它。

[source,asciidoc]
----
[.dish]
== 红烧肉

=== 火候

[.technique]
=== 炒糖色
----

《火候》没有写 role，它是《红烧肉》下的一节；《炒糖色》写了 `.technique`，查询技法时会列出它。
