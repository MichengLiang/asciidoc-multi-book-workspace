== 新增章节

新增文件：

[source,text]
----
templates/default-workspace/books/07-structured-writing-conventions/parts/100-source-surface/030-source-order-notation.adoc
----

新增章节放在第一部第三章。第一部处理源文本表面和投影，源文件编排号属于源文本表面规则。

新增章节目标正文：

[source,asciidoc]
=====
[#source-order-notation]
== 源文件编排号

源文件编排号写在 part 目录名和 chapter 文件名前部。

part 目录使用 `100-`、`200-`、`300-`。chapter 文件在所属 part 内使用 `010-`、`020-`、`030-`。

中间插入新文件时，使用相邻编号之间的空位。

[source,text]
----
parts/100-source-surface/
parts/150-new-topic/
parts/200-identity-and-relation/

010-opening.adoc
015-new-context.adoc
020-main-flow.adoc
----

标题文本保留语义名称。长期引用的标题使用显式 ID。

编排号帮助维护者观察源文件顺序；显式 ID 帮助读者和工具链稳定引用标题。
=====

新增章节的句子职责：

[cols="1,2,2", options="header"]
|===
|句子 |职责 |保留理由

|`源文件编排号写在 part 目录名和 chapter 文件名前部。`
|定义表面位置。
|删除后，读者不知道编排号写在哪里。

|`part 目录使用...`
|给出 canonical authored surface。
|删除后，读者没有可照写的表面。

|`中间插入新文件时...`
|给出结构弹性规则。
|删除后，制度不能回应插入问题。

|示例代码块
|实例化前一条规则。
|删除后规则仍成立，但读者缺少源文件表面样例；本章是标本书，保留示例。

|`标题文本保留语义名称...`
|分离标题和引用表面。
|删除后，读者不知道编排号与标题、ID 的关系。

|`编排号帮助维护者...`
|说明两个表面的职责分工。
|删除后，规则之间的对象关系不完整。
|===

== 风险控制

=== include 断裂

风险：移动目录后 `book.adoc` 仍引用旧路径。

控制：

[source,bash]
----
rg 'include::parts/0[1-3]-' templates/default-workspace/books/07-structured-writing-conventions
----

该命令应无输出。

=== anchor 污染

风险：执行时把数字编排号写进 stable anchor。

控制：

[source,bash]
----
rg '^\\[#(0|1|2|3)[0-9]' templates/default-workspace/books/07-structured-writing-conventions
----

该命令应无输出。

=== 旧路径残留

风险：正文、测试或计划外文件仍引用旧路径。

控制：

[source,bash]
----
rg 'parts/(01-source-surface|02-identity-and-relation|03-fields-and-lookup)' \
  templates/default-workspace/books/07-structured-writing-conventions test/sample-contract.test.mjs
----

该命令应无输出。

=== 新章语体偏离

风险：新增章节变成设计文档摘要或聊天解释。

控制：新增章节只允许以下句子类别：

* 表面位置。
* 表面写法。
* 插入规则。
* 源文件示例。
* 标题与 ID 的正面分工。
* 编排号与显式 ID 的职责分工。

新增章节不写以下内容：

* DDC、ISO、W3C 等理论来源。
* “不是……”开头的排除段落。
* 作者过程、计划过程或聊天解释。
* “短而硬”等自我管理词。

=== 测试误证

风险：只通过渲染或搜索就声称迁移完成。

控制：验收必须同时包含路径搜索、anchor 搜索、项目检查和 diff 范围检查。
