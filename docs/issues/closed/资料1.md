## 解决

- 解决：2026-10-21，create-asciidoc-multi-book-workspace 计划 #4 工作包 4.5；规约在 4.1（`DESIGN.adoc` 的
  Workspace Contract Checks）。
- 这份资料是 2026-06-08 05:12 随 `c6bb70e` 记下的 inkrail 现场（12 号书引用 11 号书 `book.adoc#oxigraph-adapter`，
  锚点写作 `[#oxigraph-adapter.adapter-contract, owner=query-runtime, package=oxigraph]`）。当天 14:27 的 `750e477`
  "Support typed explicit anchors in runtime checks" 让源文件检查的正则认 `[#id.role, …]`，这一例就此不再误报，
  但资料没有归档。今天在模板上照原样复现，这种写法确实通过。
- 同一族问题没有修完：正则只认以 `[#` 开头的写法。实测 `[.role#id]`、`[[id]]`、`[id=id]` 与标题生成的 ID 在 HTML
  检查里都通过，在源文件检查里都报 `MISSING_ANCHOR`。而构建里 HTML 检查排在源文件检查之前，用的是 Asciidoctor
  自己分配的 ID：锚点真缺时 HTML 检查先失败，源文件检查走到报错只可能是误报。
- 所以删去源文件层面的 xref 目标与锚点扫描（`XREF_TARGET_MISSING`、`MISSING_ANCHOR` 两个代码与五个辅助函数），
  xref 的目标与锚点只在生成的 HTML 上核对。测试 `runtime check accepts cross-book xrefs to IDs declared in any
  AsciiDoc form` 覆盖六种写法，在删除前的实现上报四条 `MISSING_ANCHOR`；`runtime check fails for a cross-book xref
  to a missing anchor` 守住真缺锚点的一侧。
- 资料里的绕行（把链接改到分卷文件 `parts/…/030-oxigraph-adapter.adoc`）在现在的检查下反而会失败：Asciidoctor
  把它写成指向 `parts/…/030-oxigraph-adapter.html` 的链接，那个文件不会生成。引用另一本书里的标题，链接写
  `book.adoc#<ID>`。
