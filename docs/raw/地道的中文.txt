## 这本书是什么

它的名字叫《**结构化书写约定标本**》，放在 asciidoc-multi-book-workspace 默认工作区模板的 `books/07-…` 下面，是一本"标本书"。它教的是怎样在一份 AsciiDoc 源文件里，同时写出**人能读的结构**和**工具能投影的结构**。

全书分三部：

| 部 | 讲什么 |
|---|---|
| 一、从源文档看结构 | 等号标题和层级；`xref` 怎样找到标题；源文件的 `0X0` 编排号（010、015、020…） |
| 二、名称、角色与关系 | 标题就是规范名称；`[#label]` 只用来保留已有的技术地址；`[.concept]` 这样的 role 写"标题在书中起什么作用"；`rel=depends-on` 这样的谓词写"两个标题之间是什么关系" |
| 三、字段与术语 | 字段少而短时写在 attrlist，多或长时写在标题下的描述列表（块用 `+` 挂上去）；`[.convention, declares=…]` 把整本书的词表写在书里 |

附录 A 是速查表，附录 B 把上面每一条都写成了"触发场景 → 一步步判断"的决策树，适合写书时随手翻。

全书反复说的其实是一件事：**每种东西只承担一个职责**。标题负责名字，寻址标签负责地址，编排号负责文件顺序，role 负责作用，rel 负责关系，别名负责旧称；跨改名追踪交给工具层的记录键，冻结版本交给内容哈希。它们互不替代。

## 它和 bookgraph 的关系

两份材料正好是一条流水线的两端：

- **写的一端**是这本书：作者照约定写下 `[.rule, verdict=adopt]`、`落点::`、`rel=derives-from`。
- **投影**由 asciidoc-abundant-tree 完成：它把这些写法变成 RDF 图，`aat:role`、`aat:containsDirectly`、`rel:depends-on` 都来自这一步（第一部第一章就有 Turtle 对照）。
- **查的一端**是 bookgraph：用 `who` 查谁引用了这个标题，用 `why` 沿 `derives-from` 往上推，用 `find(field="落点")` 在字段里找。

bookgraph 的 `Book.conventions` 读的正是这本书第三部讲的 `.convention` 声明。书里说"约定变化时只改声明，检查跟着变"，bookgraph 就是这句话的另一半，所以 `find(field=…)` 会先报出书里声明过的字段。

## 先回答你的问题：这本书给谁看

## 一、寻址：最需要讲明白的一件事

### 社区的叫法和官方立场

Asciidoctor 社区的词是这几个：

- **auto-generated ID**：从标题自动生成的 ID。
- **custom ID**：作者写的 `[#id]`。
- **natural cross reference**：直接用标题作 xref 目标。
- **reftext**：引用时显示的文字。

"显式寻址标签"是我们自己造的词。"显式"二字暗示标题地址是"隐式的"、不够正式，这正是《设位录》说的名位之失：名字替读者做了判断，而且判断反了。

更要紧的是官方的立场，原文是这样写的：

> As a rule of thumb, the natural cross reference should only be used for rapid development or short-lived content. As the content matures, you should switch to using IDs … shielded against title revisions.

也就是说，社区的默认做法正是你说的那种"欺骗"：标题改了，ID 不改，引用永远不断。这条建议是为发布到网上的文档准备的，外部链接收不回来，所以要"Cool URIs don't change"。

我们的处境不一样：书都在本地，每一处引用都在同一个仓库里，`pnpm run check` 碰到断掉的链接就会失败。在这种处境里，那层"屏蔽"保护不了任何东西，只会把改名本来应该触发的检查藏起来。你举的 Python 类改名的例子很贴切。

所以书里要**点名**这一处偏离：社区怎么说，我们为什么不这么做。懂 Asciidoctor 的读者一定会注意到这里和官方文档不一样；如果书不交代，他会以为是我们写错了。

### 实测：`[#id]` 不是"加一个别名"，而是"换掉地址"

样例在 `:idprefix:` 设为空、`:idseparator: -` 下运行，和这本书的设置一样：

| 写法 | 结果 |
|---|---|
| `xref:常规标题[]` | ✓ 能找到。原因是自动 ID 恰好等于标题 |
| `xref:role 的作用域[]` | ✓ 能找到。标题里有空格，走的是 natural xref |
| `xref:名称、角色与关系[]` | ✗ 断了。自动 ID 会去掉顿号，标题里又没有空格，natural xref 不接 |
| 标题加了 `[#src]` 以后再写 `xref:源文本与投影[]` | ✗ **断了** |
| 两个都叫"术语表"的标题 | 第二个自动变成 `术语表-2`；`xref:术语表[]` 不报错，直接落在第一个 |

第四行最能说明你的观点。官方文档说 custom ID 会"used in place of the autogenerated ID"：给一个没有空格的中文标题打上 ID，它原来的标题地址在 HTML 里就没了。在 Asciidoctor 那一侧，这不是加了一个别名，而是换了一个名字。（aat 的 label space 仍然认标题，所以图和 HTML 对这件事的看法还不一致。）

这些都是读者的先验里没有、不知道就一定会错的东西，正好应该写进书里。

### 你的规则落到书上

一个标题默认只有一个地址，就是它自己。只有它**真的需要被单独寻址**、而标题在寻址范围里又冲突（或者标题里有顿号、冒号这类没法当地址的字符）时，才给它第二个地址。

你说的"结构性小点同名"正好是 Asciidoctor 会自动加 `-2`、`-3` 的情况。这些序号跟着位置变，章节一挪就不准了。真要单独引用其中某一个，那时候再给它起名也不迟。

对照这条规则，书里现在有三处不成立：

## 二、编号：为什么要这样命名

你说的方向是对的，我补上实测里多出来的半步。编号真正的用处，是让编辑器里的文件树读起来就是目录：作者在侧栏里看到的顺序，就是书的顺序。`book.adoc` 的 include 清单才是权威，文件名只是把它映照到文件树上。

细节上，两类排序器的行为不一样。我用 `Intl.Collator({numeric:true})` 模拟 VS Code 一类的自然排序，用普通字符串排序模拟 git、Python `sorted()`、glob 这类工具：

- 自然排序：`_partintro 5-x 010-a 10-x 015-b 030-c`
- 字典序：`010-a 030-c 10-x 5-x _partintro`

可以看到，**自然排序本来就把 5 排在 10 前面**。真正会出错的是字典序工具，它会把 `10` 排到 `5` 前面。固定三位宽度的作用，是让**两类排序器排出同一个顺序**：你在 GUI 里看到的，和命令行、脚本、git 看到的一样。这才是那个"为什么"。

书上现在的理由（`030-source-order-notation.adoc:32`，"解决……编号格式的稳定"）没有把这一点说出来。附录 A 第 30 行的"首个 0 为前导零"也会误导人：真正的格式是"三位数、末位留作插入"，`090` 之后是 `100` 完全正常，宽度没变。项目里的 `关于0x0编号的设计.md` 其实也是这样推导的（主序列能放 90 个），只是书没有写准。

顺带一个小发现：`_partintro.adoc` 在 GUI 里排在第一个，正好符合阅读顺序；在命令行里却排在最后。不算错，知道就好。

## 先问清楚：这个记号标的是什么

代码注释里写的 `（8 号书 rule-layout-storage-layers）`，意思是"这段代码的依据在 8 号书的某一节"。它指向的是**某本书里的某一篇**，不是在引用一句话，也不是在说一个话题。

标准对这两种记号分得很清楚：

- **书名号**（4.15.1）："标示语段中出现的各种作品的名称"；4.15.3.1 又说它标"书名、卷名、**篇名**"。
- **引号**用来标直接引用的话，或者需要着重论述、有特殊含义的词。
- 附录 B.1.8 专门比较了这两者：一个题目如果是"诗文、图书、报告或其他作品"，可以当作篇名、书名看待，就用书名号；如果只是"写作、科研、辩论、谈话的主题"，不是某部特定作品的标题，就用引号。

书里的一个标题，就是一部特定作品里的一篇。所以引用它，语义上就该用书名号。用 `「」` 的话，读者读到的是"这句话"或"这个说法"，而不是"那一节"。

这一条一推出来，另外几件事也跟着定了。

## 推下去：书名、分隔符和嵌套

**书和篇怎么写在一起。** 标准里的例子是《史记·项羽本记》：书名和篇名放在同一对书名号里，中间用间隔号隔开。可"8 号书"不是那本书的书名，只是我们对它的称呼。把它写进书名号里，就把一个称呼冒充成了书名。所以称呼留在外面，篇名放进书名号：

```
// 布局存储分两层（8 号书《布局存储分两层》）
```

读起来就是"8 号书里的那一篇"，和平时说话一样自然。

**分隔符的问题自己消失了。** 上一轮卡住的地方，是标题里本来就有顿号和逗号，没法再拿它们当分隔符。书名号自带首尾，每个标题自己就是完整的一段。标准还专门写了："标有书名号的并列成分之间通常不用顿号"。所以引用好几节，就直接写成：

```
（8 号书《布局存储分两层》《快捷键后写者胜》）
```

根本不需要再设计分隔符。按规范写，解析也就简单了。

**标题里本身带着书名号怎么办。** 比如一节叫"读《设位录》的三失"。标准 4.15.3.5 规定，书名号里还要用书名号时，里层改用单书名号 `〈〉`，写成 `《读〈设位录〉的三失》`。这样注释里的写法就和标题原文差了一个符号。所以 bookgraph 比对时要把里层的 `〈〉` 当作 `《》`。这是很少见的情况，在设计文档里写一句就够了。

## 一、病根有五种

**1. 动作的主语错了，或者干脆没有主语。** 书里大量的句子，让"源文档""标题""本章""演示"这些东西去做只有人才做得出的动作：

- "源文档把 `常规标题` 写成可引用的阅读单位"
- "标题给出当前规范名称"
- "本章节的演示展示文字如何形成……"

你说的"把"字句正是要害。王力在《中国现代语法》里把这种句式叫"处置式"：主语有意识地处置一个对象，使它发生变化。所以"把"的前面要站一个能做主的施事。"源文档"做不了主，真正把它写成那样的是作者。中文以话题为先，常常省掉主语，这本身没问题；可是"把"、"给出"、"提供"、"展示"这些动词，本身就在要求一个施事出场。主语缺了，或者站错了人，读者就得自己去猜：到底是谁在做这件事？

**2. 言外之力含混：说不清是在描述，还是在规定。** 拿奥斯汀的三分来看：

- "同一个 role 在全书中保持同一种叙述作用"，字面上是陈述句。
- 作者想做的其实是规定（言外之力），意思是"你要让它保持同一种作用"。
- 读者读到的却是一句关于事实的话（言后之效）。作为事实它是假的：没有任何东西替你保持。

还有一类句子在谈这本书自己，比如"本章用一段示例展示结构化书写约定""本章节的演示展示……"。它们执行的言外行为是"预告"，而不是"教"。这正是《文辞误解之本末》卷二说的"文档之首忽然谈文件自身"：读者先被引去看这一章打算做什么，而这一章真正要教的东西被推到了后面。

**3. 名词堆砌，术语漂移。** 书里有一串没人定义过的词："阅读单位""源文档表面""边证据""结构坐标""层级拓扑控制""落位策略"。

同一个 role，有时叫"叙述作用"（第二部），有时叫"认知作用""认知角色"（决策树），有时叫"角色范围"（第一部）。

中英文也夹杂得没有章法：heading 和"标题"、surface field 和"附加字段"、source heading、selector、raw、token 混在一起用。术语表里中文条目和英文条目各占一半，"source-order notation"在正文里却叫"源文件编排号"。

**4. 例子和自己定的规矩打架，对象语言和元语言也搅在一起。**

你点出的 `xref:常规标题[常规标题, rel=depends-on, weight=strong]` 正是这样：显示文本照抄了一遍标题。同一本书的第二部写着"带 `rel` 的 xref 可以不写显示文本：链接显示目标标题"。这个照抄，在第一章的样例、第一部第二章、第二部第三章一共出现了三次。书嘴上讲一套，手上又示范另一套，读者会照着手上做的去学（《设位录》卷六：示例最柔，却最常被读）。

更深一层的问题出在例子的取材上。这是一本讲标题的书，可它的样例标题就叫"常规标题""基本语法""引用规则"，被讲的东西和用来讲的东西是同一套词。读到"常规标题提供可引用的阅读单位"，读者分不清这是样例书里的一句正文，还是本书在给"常规标题"下定义。用塔斯基的话说，对象语言和元语言缠在了一起。

菜谱"火候"那一段就读得很顺，原因是它的领域在书外：红烧肉是红烧肉，引用的规矩是引用的规矩，两者不会混。可惜全书的例子东一个西一个：常规标题、宿舍集中备考者、林黛玉、REQ-2024-0088、关闭标签、红烧肉，六个世界。读者每翻一节，都要重新进入一个新语境。

**5. 召来与当前事无关的东西。** 这是《忘筌录》说的"不动思、不动断者，不示"。

## 二、用屈折语照一照

把几句话放进拉丁语里，它们缺的东西就藏不住了。拉丁语的动词必须标明人称、语气和语态，名词必须标明格。

"源文档把常规标题写成可引用的阅读单位"，直译是：

> *Fons titulum ordinarium unitatem legendi citabilem facit.*

主格 *fons* 配主动的 *facit*，意思是"源头自己去做"。拉丁读者马上会问：源头会做事吗？只能改成被动 *a scriptore fit*（由作者做成），施事这才浮出来。再看 *unitas legendi*（阅读的单位），拉丁读者接着会问：是什么东西的单位？这个词背后没有所指。

"同一个 role 在全书中保持同一种叙述作用"，拉丁语逼你在两种语气之间选一个：

- 用直陈式 *servat*，就是在断言一个事实，而这个事实是假的；
- 用动形词 *servanda est*（应当保持），才是规定。

中文没有这道语法关卡，于是作者自己也没察觉到，这里得先拿定主意。

梵语的 kāraka（波你尼的"作用者"理论）照得更清楚。动词 *dā*（给）天生带着三个位置：给的人（kartṛ）、给出去的东西（karman）、接受的人（sampradāna）。"标题给出当前规范名称"这句话里，给的人是标题，接受的人缺席。更要紧的是，标题和名称之间根本不是"给"的关系，标题本身就是名称。动词选错了，句子凭空多出一场"给予"，读者就会去找那个不存在的接受者。

## 四、好的中文是怎么写的

吕叔湘、朱德熙的《语法修辞讲话》批评的，正是"主语残缺""搭配不当""用词不一致"这些毛病。叶圣陶主张"写话"：写下来的东西应该是能说出口的话。拿这个标准一试就知道，"进行导航文本""可投影的源文档表面"，没有人会这样说话。

《好书》里列的几本也指向同一个方向：

- 《风格的要素》：用主动语态，用肯定的说法，删掉不必要的词。
- 《金字塔原理》：每一部的导语先给出结论，告诉读者这一部回答什么问题。

照这些标准，规则句可以写成"role 在全书里只表示一种作用"，或者直接对读者说话："给标题写 role 时，……"。描述句要让作者或读者站出来做主语，不再让文件和标题去"给出""提供""展示"。

## 一、这一部放在哪里，叫什么

现在的三部都在讲书的骨架：标题、引用、role、字段。新的一部讲句子和篇章，是骨架上的血肉。《好书》也是这个顺序：先是思想的结构（金字塔、如何阅读），再是文笔（风格的要素），最后是形态。所以它排成**第四部，放在三部之后、附录之前**，部名就叫《文辞》。

## 二、每一条长什么样

我想借马修·阿诺德在《诗的研究》（*The Study of Poetry*，1880）里的 touchstone（试金石）：拿几句大师的诗当试金石，往别的诗上一碰，成色就看出来了。我们这一条一条的点拨正是这个用法：一个名字，一碰，心里的尺子就出来了。

```asciidoc
[.touchstone]

出处:: 王力《中国现代语法》，处置式。
自问:: 这个"把"前面站的，是能拿主意、动手处置的人吗？

（一句改前、一句改后，取自本书菜谱领域的例子）
```

这样一来，这一部同时也在示范本书的约定：

- 前言《本书的书写约定》里声明 `touchstone` 这个 role，以及它必须有的两个字段 `出处`、`自问`；
- 中文字段名、描述列表字段这些写法，在这一部里都是真的在用，而不只是代码块里的样子。

标题写的是尺子量什么，用白话写；作品放进 `出处`。标题就是地址，所以别处引用时写 `xref:"把"前面站着能做主的人[]`，读起来就是一句话。

## 冒号本来是干什么的

GB/T 15834 里，冒号的本职是这几件：

- 用在总说性、提示性的词语后面，提起下文；
- 用在总括性的话前面，总结上文；
- 用在需要说明的词语后面，引出注释和说明。

这些用法我是凭记忆说的，写进书之前会再对一遍原文。

拿这个去对照书里的冒号，它们分成两类：

- **用得对的**：比如"约定有五件：……""它核对三件事：……"。前面总说，后面分列，冒号正是提起下文。
- **不对的**：冒号在扛因果。比如：
  - "不写'上一章'这样的位置词：位置会随编排改变"，冒号后面是**原因**；
  - "不为旧标题留一节'指路'：留了，旧引用照常找到它，检查就报不出它们"，冒号后面是**一串假设和后果**；
  - "写了 role，就能按它找节：查询工具可以……"，冒号后面是**推论**。

这三处，中文书面语都会用词语来接：因为、以免、否则、若……则……。

## 它从哪里来

冒号扛因果，是英文的习惯。英文里 "Don't write X: positions change." 再自然不过，冒号和分号本来就承担逻辑连接。我们这类模型读得最多的是英文，这个习惯就跟着搬进了中文。

余光中在《论中文的西化》里，思果在《翻译研究》里，批评的都是这一类欧化中文：每个字都是中文，骨架却是英文的。

这里还有一个有意思的地方。对比语言学常说英文"形合"、中文"意合"（奈达讲翻译时就这样对举）：英文靠连接词和形态把句子扣在一起，中文靠语序和语义自然流过去，吕叔湘称之为"流水句"。可书里这些句子两头都不是：它把英文的逻辑骨架留下，把英文的连接词拿掉，换成了标点。于是读者既得不到英文那种明示的逻辑，也得不到中文那种顺着说下去的流动，只好停下来猜冒号后面是原因、例子，还是补充。

## 你脑子里冒出来的那种句式，其实有名有姓

你想到的"不应写……，以免……""当……时，……""如果出现……，则……"，正是中文规范文本的书面语体。这套语体是成文的：

- GB/T 1.1《标准化工作导则》给规范性文本的条款规定了一组能愿动词：要求用"应／不应"，推荐用"宜／不宜"，允许用"可／不必"。这和英文 RFC 2119 的 MUST、SHOULD、MAY 是一个意思。版本和具体条文，写进书之前我会去查原文。
- 理由用"以免""否则""因为"接上；条件用"当……时""如……，则……"。

拿你点的那句试一下：

> 改前：正文里提到别的部、章、节，都写成 xref，外面加书名号……；不写"上一章""第二部讲过"这样的位置词：位置会随编排改变，读者也没法从位置词跳过去。

> 改后：正文提到别的部、章、节时，应写成 xref，并在外面加书名号（见《篇名用书名号》）；不应写"上一章""第二部讲过"这类位置词，以免编排调整后指错地方，读者也无法从位置词跳转到那一节。

再试一句：

> 改前：不为旧标题留一节"指路"：留了，旧引用照常找到它，检查就报不出它们。

> 改后：改名后不应为旧标题保留一节"指路"。若保留，旧引用仍能找到它，检查便无从报出这些引用。

改后的句子，读者一读就知道哪个是规定、哪个是理由、哪个是后果，不用猜。

还有一层是**语体混杂**：书里夹着不少口语词，比如"没法""跳过去""照写不误""用开以后""心里要装着"。书面语不是要写成公文腔，而是要用一种稳定的、能写下来的语体：规定句用"应、宜、可"，说明句平实地讲。说到这里，吕叔湘《现代汉语八百词》、《现代汉语词典》的凡例，都是很好的样子：简短，书面，不端架子。
