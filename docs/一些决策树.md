#### 决策树 1：标题生成与层级拓扑控制

```text
触发场景：创作者准备在源文档中创建一个新的标题节点

1. 评估节点全局定位：该标题是否为文档大标题（Document Title）？
   ├─ [是] -> 执行动作：使用 `= 书名` 语法。
   │          位置约束：放置于文档首行。
   │          (流程结束)
   └─ [否] -> 进入逻辑层级评估。

2. 评估逻辑层级：当前标题的预期层级，与紧邻的上一级标题层级关系为何？
   ├─ [跨级向下（如跳过 == 直接写 ====）] -> 状态：不符合物理层级映射规则。
   │                                         执行动作：补充中间层级标题，保持层级连续。
   │                                         (返回节点 2 重新评估)
   └─ [层级连续（同级或逐级向下）] -> 进入区域划分评估。

3. 评估引用需求：当前标题下的文本区域，后续是否存在被精准指向或提及的需求？
   ├─ [是] -> 执行动作：使用更小一级/更小一节的标题等号语法，将该区域独立划分。
   │          后续操作：使用 xref 对该更小一级标题进行交叉引用。
   │          (流程结束)
   └─ [否] -> 进入段落语义评估。

4. 评估段落整体语义：当前标题后的内容是否属于特定的附录或后置结构？
   ├─ [是] -> 执行动作：在等号标题上方，按需声明 Section Style（`[appendix]`, `[glossary]`, `[bibliography]`, `[index]`）。
   │          状态声明：改变紧随其后 section 的语义，标题层级仍由 `=` 数量决定。
   │          (流程结束)
   └─ [否] -> 执行动作：写入标准等号标题。
              (流程结束)

```

#### 决策树 2：稳定 ID (Stable ID) 的生命周期与寻址机制

```text
触发场景：评估是否需要为当前标题显式声明寻址 ID

1. 评估文本唯一性：当前标题文本是否已是领域内唯一且稳定的标识符（如专有名词、标准化编号）？
   ├─ [是] -> 执行动作：不声明 [#stable-id]。
   │          后续操作：直接使用标题文本作为引用地址（如 `xref:标题文本[]`）。
   │          (流程结束)
   └─ [否，文本可能变更或重复] -> 进入引用预判评估。

2. 评估交叉引用状态：该标题在全书范围内，是否被至少一个 `xref` 交叉引用？
   ├─ [否] -> 执行动作：不声明 [#stable-id]。
   │          (流程结束)
   └─ [是] -> 执行动作：在等号标题上方的 attrlist 中显式声明 `[#stable-id]`。
              (流程结束)

====================================================
触发场景：项目全局构建或审查阶段（后置校验）

3. 全局一致性审查：扫描源文件中所有手工显式声明的 `[#stable-id]`。
   ├─ 状态 [每个 ID 对应的 xref 引用次数 >= 1] -> 判定：符合规范。
   │                                              (审查通过)
   └─ 状态 [某个 ID 对应的 xref 引用次数 == 0] -> 判定：存在未被消费的节点。
                                                  执行动作：移除该 `[#stable-id]` 声明。

```

#### 决策树 3：节点身份（Role）的作用域与语境管理

```text
触发场景：为标题标记认知功能与身份语义

前提：文档所属项目已就领域概念结构，约定了语义唯一且不变的《受控词表》（如 `.concept`, `.rule`, `.example`）。

1. 评估上下文：当前标题是否为其父标题的下级标题（子标题）？
   ├─ [否，当前是顶层 0级/1级 标题] -> 执行动作：从受控词表中选取匹配当前语境的 role，写入标题 attrlist（如 `[.role]`）。
   │                                  (流程结束)
   └─ [是，当前为下级标题] -> 进入语境继承评估。

2. 评估语境连续性：当前子标题所承载的认知角色，是否与父标题声明的 role 相同？
   ├─ [是] -> 执行动作：保持标题声明空白（不写 role）。
   │          底层状态：下级标题默认属于同一角色范围，自动继承语境。
   │          (流程结束)
   └─ [否] -> 执行动作：从受控词表中选取匹配新语境的 role，显式写入当前子标题 attrlist。
              底层状态：下级标题声明不同角色，完成语境切换。
              (流程结束)

```

#### 决策树 4：交叉引用（Xref）与边关系谓词建立

```text
触发场景：在正文中执行指向其他节点的交叉引用

1. 评估物理跨度：当前引用是否跨越了 `= 书名`、`= 卷/部`、`== 章` 等大跨度指代？
   ├─ [是] -> 执行动作：手动写入 `xref` 进行标注。
   │          目的状态：平衡隐式上下文的阅读压力。
   │          (进入关系评估)
   └─ [否] -> 进入跨文件评估。

2. 评估文件位置：目标标题是否位于不同的物理源文件中？
   ├─ [是] -> 执行动作：在当前文档头部定义文档属性（如 `:book-b-dir:`）存储基础路径。
   │          后续操作：通过 `{book-b-dir}` 调用变量进行跨文件引用。
   │          (进入关系评估)
   └─ [否] -> 进入关系评估。

3. 评估逻辑关系意图：引用的目的为何？
   ├─ [表达阅读顺序、先读建议或普通参见] -> 执行动作：写入普通 xref（`xref:target-id[显示文本]`）。
   │                                        投影状态：投影为默认谓词 `aat:references`。
   │                                        (流程结束)
   └─ [声明明确的逻辑关系边] -> 进入受控谓词选取。

4. 选取关系谓词（`rel`）：根据约定的全书唯一语义词表选择边谓词（以下为样本选项）。
   ├─ [当前标题的判断、规则或操作以目标为依据] -> 执行动作：在 named attributes 中注入 `rel=depends-on`。
   ├─ [当前标题提供目标标题的示例] -> 执行动作：在 named attributes 中注入 `rel=illustrates`。
   ├─ [当前标题给出目标标题所代表对象的定义] -> 执行动作：在 named attributes 中注入 `rel=defines`。
   └─ [当前标题对目标标题的合法写法或范围施加约束] -> 执行动作：在 named attributes 中注入 `rel=constrains`。

```

#### 决策树 5：附加字段（Surface Fields）落位策略

```text
触发场景：为标题（节点）或引用（边）挂载元数据/键值对

1. 评估字段从属对象：该字段描述的主体是什么？
   ├─ [描述 xref 引用边（如权重 weight=strong）] -> 执行动作：将字段写入 xref 的 named attributes 中。
   │                                                 (流程结束)
   └─ [描述 Heading 标题节点（如 owner, priority）] -> 进入数据体积评估。

2. 评估字段体积：该标题涉及的附加字段数量及长度为何？
   ├─ [字段数量较少，且所有字段值均较短（无换行需求）] -> 执行动作：将字段写入标题前方的 attrlist 中（如 `[owner=writing-team, status=active]`）。
   │                                                      (流程结束)
   └─ [字段数量较多，或包含需要换行的多行字段值（如 summary）] -> 执行动作：在紧随该标题的下方，写入第一个连续的描述列表（Description Lists）。
                                                                  语法示例：`key:: value`。
                                                                  (流程结束)

```

#### 决策树 6：源文件物理编排与编号运算

```text
触发场景：为 Part 目录或 Chapter 源文件生成文件编排号

约束前提：统一使用三位数 `0X0` 格式。X为递增号，首部前导零，尾部插入预留零。初始序列步长为 10（010, 020, 030）。

1. 评估内容落位意图：新文件在逻辑序列中的位置为何？
   ├─ [位于当前既有序列的最后方] -> 进入末尾追加操作。
   └─ [位于当前既有的文件 A 与文件 B 之间] -> 进入中间插入操作。

2. 执行末尾追加操作（Append）：
   执行动作：提取当前同级列表中的最大编号，将其十位数字加 `1`，个位保持 `0`。
   (流程结束)

3. 执行中间插入操作（Insert）：
   执行动作：提取上文文件 A 和下文文件 B 的编号，计算两者的算术中间值。
   状态结果：生成新编号（如在 010 与 020 之间取 015），维持物理顺序并保留二次插入空间。
   (流程结束)

```

#### 决策树 7：索引词（Index Term）落位与特殊语法处理

```text
触发场景 A：为读者检索和书后索引添加索引入口（埋点）

1. 评估词汇可见性状态：该索引目标词，在当前正文的句子里是否已经自然出现？
   ├─ [是] -> 执行动作：使用正文可见索引词宏 `indexterm2:[<primary>]` 包裹该词。
   │          系统状态：正文保持可见，同时提取为一级索引项。
   │          (流程结束)
   └─ [否，正文未出现该词，需隐式补充] -> 进入隐式埋点操作。

2. 执行隐式埋点操作：
   执行动作：使用正文隐藏索引词宏 `indexterm:[<primary>]`（按需支持多级如 `<primary>, <secondary>`）。
   物理位置约束：隐藏索引词宏应贴近标记段落内容，置于相关句子的末尾。
   (流程结束)

====================================================
触发场景 B：文档包含代码、日志或工具语法文本

3. 评估语法冲突：正文中是否出现了 AsciiDoc 原生语法字符，且需阻止其被解析引擎渲染？
   ├─ [是] -> 执行动作：使用 `pass:[]` 宏包裹该内容表达透传。
   │          补充操作：若需代码字体样式，可在外层叠加反引号包裹。
   │          (流程结束)
   └─ [否] -> 进入逻辑分离评估。

4. 评估解释关联：当前是否为“代码/日志”结构，且配有单独的“文字解释”？
   ├─ [是，且需要分离展示] -> 执行动作：使用 Asciidoc 内置的 Callouts 机制进行标注与解释关联。
   │                          (流程结束)
   └─ [否] -> 正常书写。

```
