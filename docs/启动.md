## 结论：不能直接运行 `src/*.ts`，要先让 `tsc` 编译出一份 `dist/`，再运行 `node dist/create.js`

我试了 `node src/create.ts tmp/x --solo`（Node 24.14.1 原生做类型剥离），立刻失败：

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find module '.../src/init-workspace.js'
imported from .../src/create.ts
```

原因是源码按 NodeNext 风格写成了 `.js` 后缀导入（`src/create.ts:4`、`src/index.ts:1`），而 Node
的类型剥离只去掉类型标注、不改写导入路径，因此找不到对应文件。

另外，生成器本身依赖编译产物：`src/init-workspace.ts:24-27` 用 `import.meta.url` 推出包根，模板根是
`<包根>/templates`，用户运行时脚本是 `<包根>/dist/runtime/adoc-books.mjs`，创建时再原样复制成生成工作区的
`tools/adoc-books.mjs`（`src/init-workspace.ts:83-84`）。所以 `dist/runtime/adoc-books.mjs` 必须先存在。

## 命令可以长成什么样子

当前仓库里 `dist/` 已经构建好了（`dist/create.js`、`dist/index.js`、`dist/runtime/adoc-books.mjs` 都在），而现在就可以直接运行：

```bash
cd /home/t103o/workbench/micheng-ts/projects/asciidoc-multi-book-workspace

# 默认：完整八本书的工作区
node dist/create.js /home/t103o/workbench/micheng-ts/my-books

# solo：只有一本 07，挂在 books/01-structured-writing-conventions
node dist/create.js my-book --solo

# 目标目录非空时覆写模板产出的路径，其它文件保留
node dist/create.js my-books --force

# 没给 target 就打印 usage 并 exit 1
node dist/create.js
```

这里的「从任意目录运行」我实测通过：模板和运行时都按模块自身位置解析，**只有 target 相对当前 cwd
解析**（`src/create.ts:31`、`src/init-workspace.ts:60` 的 `path.resolve`）。所以：

```bash
cd /tmp
node /home/t103o/workbench/micheng-ts/projects/asciidoc-multi-book-workspace/dist/create.js ./adoc-probe --solo
```

也照样生成，并且 `--help`/`-h` 会打印一段和 `pnpm create` 并列的用法示例。

改了 `src/` 之后要重编：

```bash
pnpm run build     # 即 tsc -p tsconfig.json，产出 dist/*.js + dist/runtime/adoc-books.mjs
node dist/create.js /path/to/新工作区
```

注意 `dist/` 被 `.gitignore` 忽略，所以新克隆下来必须先 build 一次，否则 `dist/create.js` 不存在。

## 另一条路：直接当库调用

不需要 CLI 的参数解析时，用生成好的 ESM 入口就行（我实测通过）：

```bash
node --input-type=module -e '
import { initSoloWorkspace } from "/home/t103o/workbench/micheng-ts/projects/asciidoc-multi-book-workspace/dist/index.js";
console.log(await initSoloWorkspace({ targetDir: "/tmp/adoc-probe-api" }));
'
```

它返回 `{ targetDir, packageName }`。`initWorkspace` / `initSoloWorkspace` 的差别只是复制表不同（`src/template-manifest.ts`）。

## 生成完以后在新工作区里做什么

生成的 `package.json` 自带两个脚本，运行时脚本属于用户自己：

```bash
cd my-books
pnpm install
node tools/adoc-books.mjs build    # 或 pnpm run build
node tools/adoc-books.mjs clean
```

`build` 之后打开 `build/html/index.html`。`tools/adoc-books.mjs` 的 CLI 极简，只认 `build` 和
`clean`（`tmp/probe-default/tools/adoc-books.mjs:1240-1253`），其余一律打印 `Usage: node tools/adoc-books.mjs <build|clean>` 并
exit 1。

## 补充两点观察

- `package.json` 里的 `bin` 指向 `dist/create.js`，所以 `pnpm create asciidoc-multi-book-workspace x` 走的与上面 `node
dist/create.js x` 是同一个文件；直接 Node 运行只是在绕过包管理器那一层。
- 实测行为细节：目标目录非空且没加 `--force` 时，报 `target directory is not empty: <绝对路径>` 并 exit 1；输出里 `Created ... in
<相对 cwd 的路径>`，所以从别的目录运行会看到 `../` 之类的前缀。

验证用的 `tmp/probe-default`、`tmp/probe-solo`、`tmp/probe-api` 和 `/tmp/adoc-probe-elsewhere` 都已清理，`git status` 干净。
